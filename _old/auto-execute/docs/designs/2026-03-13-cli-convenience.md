# Design: CLI Convenience for auto-execute

**Date:** 2026-03-13
**Status:** Approved

## Problem

Calling auto-execute requires typing the full script path and named parameters:

```powershell
& "C:\Users\vadash\.claude\skills\auto-execute\auto-execute.ps1" -Plan "docs/plans/2026-03-13-markdown-link-checker.md" -ClaudeBin "claude_stable_ali"
```

This is verbose and error-prone. The goal is:

```powershell
auto-execute 2026-03-13-markdown-link-checker claude_stable_ali
```

## Design

Two small changes. No new wrapper script, no architectural changes.

### 1. `install.ps1` (new file)

One-time setup script. Run it once to make `auto-execute` callable from anywhere.

**What it does:**
- Adds `C:\Users\vadash\.claude\skills\auto-execute` to user PATH via `[Environment]::SetEnvironmentVariable('PATH', ..., 'User')`
- Creates `auto-execute.cmd` shim alongside `auto-execute.ps1` for cmd.exe compatibility
- Idempotent — detects if already installed, skips if so

**The `.cmd` shim** (generated by install.ps1):
```cmd
@echo off
powershell -NoProfile -File "%~dp0auto-execute.ps1" %*
```

PowerShell natively resolves `auto-execute` → `auto-execute.ps1` when the directory is in PATH. The `.cmd` shim covers `cmd.exe` and other shells.

### 2. Modified `auto-execute.ps1` param block

Make `$Plan` and `$ClaudeBin` positional. Add partial-name resolution before pre-flight.

**Param changes:**
```powershell
param(
    [Parameter(Mandatory, Position=0)] [string] $Plan,
    [Parameter(Position=1)] [string] $ClaudeBin = "claude",
    # ... rest unchanged
)
```

**Resolution logic** (inserted before Phase 1a):
```
if $Plan is an existing file path → use as-is (backward compat)
else → glob docs/plans/*$Plan*.md in current working directory
  1 match  → use it
  0 matches → error: "No plan matching '$Plan' in docs/plans/"
  2+ matches → error: "Ambiguous plan name '$Plan'. Matches:" + list
```

### Calling conventions

All of these work:

```powershell
# New short form (from project root)
auto-execute 2026-03-13-markdown-link-checker claude_stable_ali

# Partial match
auto-execute markdown-link claude_stable_ali

# Old explicit form (backward compat)
auto-execute -Plan "docs/plans/2026-03-13-markdown-link-checker.md" -ClaudeBin claude_stable_ali

# ClaudeBin defaults to "claude"
auto-execute markdown-link
```

### What doesn't change

- Main execution loop, helpers, hooks, SKILL.md — untouched
- The resolution logic runs before any existing code
- All existing `-Plan "full/path"` calls continue to work
